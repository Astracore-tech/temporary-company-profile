# Launch runbook and technical handover

## Source and deployment

The rebuild is a React/TypeScript application using the Next-compatible Vinext runtime on Cloudflare Workers. It is prepared as an isolated replacement under `rebuild/` in the existing GitHub repository. The current main branch and GitHub Pages deployment are not overwritten. The private Sites deployment is a review environment with noindex headers.

The existing static GitHub Pages target cannot alone run the scanner, D1 lead storage, or root edge routing. Production migration must use a server/edge runtime and bind the real domain. Sites provisions DB for the review environment; an external Cloudflare deployment needs corresponding DB bindings, migrations, and runtime variables. Do not deploy this as a static export.

## Routes

`/` redirects at the edge to `/ke/` for Cloudflare continent AF; other/unknown locations go to `/us/`. A manual region choice takes priority via an HttpOnly preference cookie. Direct regional URLs never redirect based on location. Region redirects use private/no-store to prevent geography being cached across visitors.

Regional pages emit reciprocal en-KE, en-US, en, and x-default alternates and self-canonicals. /us is the global English fallback. There is no en-Africa pseudo-code. Structured data includes Organization and service-level Service objects; no invented physical address or US office is included. Add LocalBusiness only when a real publishable business address is verified.

The sitemap includes regional pages and articles; reports, admin, and APIs are excluded. robots.txt disallows all crawling on the review hostname. On astracoretech.org it allows marketing pages and disallows private functional routes. The Worker adds noindex to all non-production hostnames and to report/admin/API responses.

## Runtime secrets

- ADMIN_EMAIL: server-only owner allowlist, configured for the review Site. Requires trusted Sites identity headers and a signed-in user ID. Do not trust arbitrary forwarded identity headers when porting to another host.
- ADMIN_TOKEN: a cryptographically random secret of at least 32 characters. Configure through the hosting secret store. Optional fallback to load/update/delete leads at `/admin/`. Never commit it or put it in a URL. Rotate it when access changes. The UI holds it in tab memory only.
- PAGESPEED_API_KEY: optional Google PageSpeed Insights API key. Improves quota predictability. Server-only.

No automated outbound email or WhatsApp integration is currently configured. Leads are stored in DB and visible to the authorised owneristrator. Report email uses the visitor's mail application. Before a public launch, connect transactional delivery or assign a reliable lead-desk review owner; do not promise that a notification has been sent.

## Database

D1 binding DB. Migrations are generated by Drizzle and applied by Sites at deployment. Tables: leads, reports, limits. Reports expire after seven days; expired reports are not served and are removed during later form/scan requests. Rate limits are per hashed network address and hourly bucket. Enquiries require explicit response consent. Admin supports status changes and deletion. The configured ADMIN_EMAIL can access it through trusted Sites identity headers; a token is an optional fallback. Review unconverted enquiries after 90 days as an operational task.

## Scanner scope and security

Requires an affirmative ownership/permission check. HTTPS domains only; strips query/fragment; rejects credentials, nonstandard ports, IP literals, private/reserved DNS answers, local names, and unsafe redirect schemes. DNS answers are checked using Cloudflare DNS-over-HTTPS. Each redirect is revalidated; only the submitted host or its www counterpart is allowed for the main page. Sample link checks stay same-origin and use HEAD only, with obvious action-like routes excluded. No form submissions, login attempts, full crawling, or exploit checks.

The scanner is a lightweight server-side HTML snapshot, not a full vulnerability assessment. It checks title, meta description, H1, canonical, JSON-LD parseability, viewport, HTTPS, headers, and up to three links. A configured/available PageSpeed request provides a mobile lab performance score. It does not claim a true mobile render or functioning form delivery from static markup.

Limits: five scans/hour/network address; 1.5 MB HTML; bounded per-request timeouts and redirect count. Public launch should add edge-level abuse controls. DNS preflight is not a replacement for network-level egress isolation; run only on the intended Cloudflare runtime, which must not expose internal services through this code. Do not port to an unrestricted internal network without a pinned-address outbound proxy or equivalent egress policy.

Reports use random UUID links and noindex/no-store. They contain no submitted contact information. They are bearer links: anyone holding one can read the report during its lifetime. Private review deployment authentication still applies to sharing until a public launch.

## QA and launch checklist

1. Type-check and production build.
2. Verify security/unit tests and generated migrations.
3. Browser-test desktop and narrow mobile pages, keyboard focus, menus, form validation, error handling, region switching, and report print layout.
4. Run a check against a website the owner authorises; confirm DNS, error, redirect, rate-limit, report expiry, and PageSpeed availability paths.
5. Test lead create/update/delete with real D1 and the authorised owner, using clearly labeled test data and removing it afterwards.
6. Configure DNS/SSL and confirm both regional contact numbers and email ownership. Preserve domain mail records.
7. Map old URLs to regional equivalents at the edge; retain only verified case studies. Do not invent replacement case study routes for old sample claims.
8. Run PageSpeed mobile from both market conditions. Target 90+, but report actual scores and field data honestly. No large raster assets or external fonts are used in the new UI.
9. Confirm final legal details, contracts, costs, trial capacity, lead-response owner, and creator supply.
10. Connect Search Console and submit the production sitemap. Verify live canonicals, hreflang, status codes, and indexability.

## Rollback

Keep the previous repository commit and host configuration. Launch in a controlled window with DNS rollback documented. If lead capture or critical routing fails, restore the previous origin while correcting the rebuild. Export and reconcile newly received leads before any database replacement.
